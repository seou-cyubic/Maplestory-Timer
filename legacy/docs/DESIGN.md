# 종합 설계

## 1. 성공 조건과 미확정 사항

5개 이벤트를 구분하여 소리로 알리고, 왜 알렸는지 짧은 근거를 화면에 표시한다. 정상 사냥에서의 오탐과 중요한 상황의 미탐을 함께 줄인다. 최고 성능은 실게임 데이터로 측정해야 하므로 특정 모델의 우수함이나 정확도를 미리 보장하지 않는다.

확정된 입력: 한국 메이플스토리 화면, 사용자 제공 지속시간(비약 1,800초 / 부스터 100초).
확정 환경: Windows 11, 듀얼 QHD, 창 모드 1366×768. 경험치 하단 정수 표시가 7,000ms 이상 증가하지 않으면 사냥 중단이다. 부스터는 중앙 상단 타이머, 비약은 우측 상단 아이콘의 시간·명암을 관측한다. 미확정: GPU·DPI, 아이콘과 팝업 변형, 부스터 시간의 실제 표시 형식, 부스터 정확한 명칭. 질문 답변과 사용자 영상이 게임 규칙의 우선 근거다.

## 2. 기술 스택과 선정 이유

| 계층 | 기본 선택 | 이유 / 대안 전환 조건 |
|---|---|---|
| 애플리케이션 | Python 3.12 x64를 초기 호환성 기준으로 검토 | OpenCV·데이터 분석·추론을 한 언어로 반복 개발. 실제 설치 전 패키지 호환성을 확인하고 버전을 잠금 |
| 데스크톱 UI | PySide6 | ROI 선택, 상태 표시, 설정, 트레이, 소리 테스트. 배포 시 Qt 라이선스 고지 및 배포 요건 확인 |
| 화면 캡처 | Windows Graphics Capture(WGC) 어댑터 | 게임 창 단위 캡처를 우선 실험. Python 바인딩 연결이 불안정하면 작은 C++ 캡처 모듈을 같은 인터페이스로 대체 |
| 캡처 대안 | Desktop Duplication 기반 어댑터 | WGC가 해당 환경에서 실패할 때 비교. 화면 캡처는 다른 창에 가려지면 그 내용을 읽을 수 있으므로 동등한 보장으로 취급하지 않음 |
| 전처리·고전 인식 | OpenCV + NumPy | ROI, 정규화, 템플릿, 색상·윤곽, 광류, 추적 |
| OCR | 숫자·시간용 제한 인식기부터, 한국어는 PaddleOCR 후보 | 전체 화면 OCR을 피하고 후보 ROI에서만 실행. 실제 폰트·크기로 비교 후 선택; OCR 엔진은 교체 가능 |
| 선택적 학습 | PyTorch 학습 → ONNX Runtime CPU 추론 | 아이콘·팝업의 변형 또는 행동 구분이 기존 방식으로 합격 기준을 못 맞출 때 도입 |
| 오디오 | Qt QSoundEffect + 사전 생성 WAV | 이벤트별 짧고 구별되는 소리, 장치 선택·볼륨·테스트. 실시간 TTS 의존 없이 동작 |
| 데이터 | JSON 설정 + SQLite 이벤트 + 로컬 이미지/클립 | 모델·설정 버전과 판정 근거 재현, 원시 화면 보관은 별도 선택 |
| 검증·배포 | pytest, 녹화 재생 평가기, PyInstaller 후보 | 시간 상태 로직과 실제 이벤트 단위 평가. Windows 대상 PC에서 패키징 검증 |

WGC는 창 또는 디스플레이 프레임을 제공하는 Windows API다. 최소화·독점 전체 화면·캡처 제한 등은 대상 환경에서 별도 확인한다. [Microsoft 공식 문서](https://learn.microsoft.com/en-us/windows/uwp/audio-video-camera/screen-capture)

템플릿 매칭은 작은 패턴 탐색, 광류는 프레임 사이의 영상 움직임 추정에 사용한다. 움직임 자체를 캐릭터 행동으로 해석하지 않는다. [OpenCV 템플릿](https://docs.opencv.org/4.x/d4/dc6/tutorial_py_template_matching.html), [OpenCV 광류](https://docs.opencv.org/4.x/d4/dee/tutorial_optical_flow.html)

CPU 추론을 기본으로 측정하고 병목일 때만 GPU를 검토한다. Windows의 ONNX Runtime 문서는 DirectML보다 WinML을 향후 경로로 안내하므로 DirectML에 설계를 고정하지 않는다. [ONNX Runtime Windows](https://onnxruntime.ai/docs/get-started/with-windows.html)

짧은 알림음은 QSoundEffect로 구현한다. [Qt 공식 문서](https://doc.qt.io/qtforpython-6/PySide6/QtMultimedia/QSoundEffect.html)

## 3. 실행 파이프라인

```text
창 선택 → 캡처 → 프레임 유효성 → UI 위치·배율 확인 → ROI 분리
          ↓                                     ↓
     캡처 상태 표시             5개 검출기 → 시간 상태 판정 → 이벤트
                                                      ↓
                                            우선순위·중복 제어 → 소리
                                                      ↓
                                               근거·지연 로그
```

UI 스레드는 화면·오디오를 담당하고, 캡처 스레드는 가장 최근 프레임만 교체한다. 분석 워커는 제한된 큐로 작업한다. OCR·모델은 필요할 때 별도 워커로 보내며, 늦게 돌아온 결과는 frame_id와 profile_epoch로 폐기한다. 프레임이 쌓여 오래된 화면을 판정하지 않게 한다.

초기 캡처 15 FPS, 팝업 10 Hz, 경험치 10 Hz, 미니맵 5 Hz, 버프 2 Hz, 일반 OCR 1 Hz(경험치 숫자 인식은 별도 10 Hz)를 제안한다. 이는 성능 측정 후 조정하는 값이다. 과부하 시 OCR·비긴급 분석부터 줄이고 팝업·캡처 건강 상태를 우선한다.

### 프레임 유효성과 좌표

- Frame: id, monotonic_timestamp, capture_timestamp, window_id, client_size, profile_epoch, image, capture_health.
- ROI는 게임 클라이언트 좌표의 정규화 사각형(x/W, y/H, w/W, h/H)으로 저장한다. Windows DPI와 창 테두리를 보정한다.
- 정규화 좌표만으로 UI 재배치를 해결하지 않는다. 미니맵 테두리·버프 영역 등 앵커로 확인하고 크기 변화 시 재획득한다.
- 해상도·UI 배율별 템플릿 묶음을 사용한다. 극소형 아이콘을 과도하게 축소하지 않는다.
- 캡처 실패, 검은 프레임, 다른 창, 오래된 타임스탬프, ROI 유실은 UNKNOWN. 신선한 동일 화면은 실제 정지일 수도 있으므로 이미지 해시만으로 캡처 실패를 확정하지 않는다.
- 최소화·로딩·맵 전환 중 해당 검출기의 관측을 중단한다. 캡처 장애는 별도 상태 알림으로 나타내며 버프 종료·사냥 중단으로 대신 알리지 않는다.

## 4. 공통 관측·상태 로직

Observation = {event_type, frame_id, timestamp, profile_epoch, visibility: VISIBLE|OCCLUDED|UNKNOWN, evidence: PRESENT|ABSENT|AMBIGUOUS, score, bbox, features, reason}.

score는 알고리즘 점수이며 자동으로 확률을 뜻하지 않는다. 검증 데이터로 검출기별 임계값을 선택한다. 서로 상관된 템플릿 점수를 독립 확률처럼 곱하지 않는다.

등장형 상태: UNKNOWN → ABSENT → CANDIDATE → PRESENT → CLEARING → ABSENT.
사용 시작 시 이미 존재하는 룬·팝업도 최초 확인 이벤트를 한 번 발생시킨다. 후보 확정은 실제 시간 구간과 최소 관측 수를 모두 만족해야 한다. 예: 0.3초 이상에 걸친 유효 관측 3회. 같은 프레임 재분석은 추가 증거가 아니다.

가림은 ABSENT가 아니며 상태를 불확실로 만든다. 장시간 가림 뒤 복귀한 동일 상황은 짧은 가림에서처럼 무조건 신규 이벤트로 만들지 않는다. 명확한 소멸·재등장 또는 장면 세대 변경을 재무장 근거로 사용한다.

소멸형 상태: UNSEEN → ACTIVE → MISSING_CANDIDATE → ENDED. UNKNOWN 관측은 종료 후보 시간에 더하지 않고 연속 부재 확인을 초기화한다. ACTIVE가 한 번도 확인되지 않았다면 앱 시작 직후 아이콘이 없다고 종료를 알리지 않는다.

시간 계산은 monotonic clock을 사용한다. 중단·절전·재시작 이후 이전 타이머는 참고값으로만 복원하고 화면으로 재확인한다. 관측 중단 구간을 사냥 중단 시간으로 누적하지 않는다.

## 5. 이벤트별 알고리즘

### 5.1 룬 등장

입력: 미니맵 전체와 미니맵 유효성. 색상 범위와 연결 성분으로 후보를 찾고, 복수 템플릿·윤곽으로 확인한다. 크기별 스케일은 캘리브레이션 주변으로 제한한다. 색상 단독 판정은 쓰지 않는다.

다른 마커·포털·플레이어·겹침을 음성 예제로 확보한다. 동일 위치 주변 후보를 추적하되 맵 변화 시 위치 추적을 초기화한다. 초기 확정 조건은 0.4초 이상, 유효 양성 3회; 소멸은 유효 부재 2초로 제안한다. 지속 노출 동안 한 번 알리고, 실제 소멸 후 재등장하면 새 이벤트로 알린다. 룬 종류별 색상·모양은 사용자 자료로 확정한다.

### 5.2 소형 재물 획득의 비약 종료

입력: 버프바 전체. 아이콘 위치가 이동하므로 특정 슬롯을 고정 감시하지 않는다. 아이콘의 시간 숫자·깜빡임 영역을 제외한 특징으로 식별하고 유사 비약 아이콘과 비교한다. 가림이 없는 버프 영역에서 재검색 후 소멸을 확인한다.

ACTIVE 확인 이후 아이콘 부재가 유효 관측으로 3초 지속되면 종료 후보를 확정한다. 단, UI 접힘·오버플로·아이콘 숨김이 있거나 그 여부를 판단할 수 없으면 UNKNOWN으로 둔다. 버프바가 실제로 모든 관련 아이콘을 표시하는지 캘리브레이션에서 확인해야 한다.

시간 OCR은 해당 아이콘 주변만 읽는다. 사용자 확인에 따라 10분 이상은 아이콘 좌하단의 흰색 분 숫자를, 10분 미만은 중앙의 큰 노란색 m:ss를 읽는다. 마우스 호버 없이 관측 가능하다. 허용 범위와 시간 감소 일관성을 확인한다. 한 번의 읽기보다 최근 여러 값의 중앙값과 경과시간 잔차로 만료 시각을 추정한다. 값이 커지면 갱신 후보로 보고 반복 관측 후 타이머를 새로 잡는다.

앱을 버프 도중 켰다면 1,800초를 새로 시작하지 않는다. 잔여시간을 읽을 수 없으면 남은 시간은 미상이다. 예측 만료가 왔어도 화면 확인이 불가능하면 '비약 종료 예상·확인 필요'로 별도 알림한다. 실제 종료 알림과 구별하며 중복 알림을 합친다. 정상 소멸과 임의 해제의 구분 신호가 없다면 문구는 '비약 효과가 보이지 않습니다'로 제한한다.

### 5.3 사냥 일시 정지 — 경험치 정수 추적

확정 정의: 화면 최하단 경험치 바 안의 현재 경험치 정수가 7,000ms 이상 증가하지 않으면 알린다. 사용자 예시: `79,580,389,573,127 [72.700%]`. 제자리 공격이므로 움직임·공격 모션 검출은 필요하지 않다. 다만 경험치 정체는 공격 정지의 대리 지표이므로 공격 중 경험치를 얻지 못하는 상황도 요구 정의상 중단으로 판정한다.

하단 ROI에서 정수 부분과 퍼센트를 분리한다. 정수는 부동소수점 변환 없이 Python int로 파싱한다. 쉼표 위치와 숫자 집합을 검증하며 퍼센트는 보조 검증에만 사용한다. 경험치 게이지의 픽셀 변화나 소수점 세 자리 퍼센트를 주 판정으로 쓰지 않는다.

숫자 영역은 원본 해상도에서 잘라 2~3배 확대, 명암 정규화, 복수 이진화 후보 중 검증된 방식으로 읽는다. 일반 한국어 OCR보다 숫자 전용 인식을 우선 비교한다. 초당 10회 관측을 초기 목표로 하고 실제 CPU 비용을 측정한다.

기준선 설정 시 유효 정수 2회로 초기 오독을 줄인다. 값 증가 후보는 다음 관측에서 이전 기준선보다 크거나 같은 새 값으로 뒷받침되는지 확인한다. 빠르게 경험치가 증가할 수 있으므로 동일 숫자가 연속해서 나오는 조건은 요구하지 않는다. 오독 의심 큰 점프는 원본 재인식·퍼센트 일관성으로 확인하며, 불확실한 값은 기준선에 반영하지 않는다.

- 증가 확인: 최초 증가 후보 프레임 시각을 last_increase로 기록하고 idle 누적을 0으로 초기화.
- 같은 값: 연속 유효 관측 구간에서 정체 시간을 계산.
- 7,000ms 도달: 해당 프레임의 증가 검증을 먼저 처리한 뒤 정체가 유지되면 한 번 알림.
- OCR 실패·ROI 가림·긴 프레임 공백: UNKNOWN으로 전환, 연속 정체 구간을 끊고 복귀 후 재기준화. 관측하지 못한 7초를 정체로 확정하지 않음.
- 정수 감소: 레벨 표시 증가가 확인되면 레벨업에 따른 재기준화. 확인할 수 없는 감소는 UNKNOWN으로 두고 새 기준선을 획득. 감소를 정상 증가로 꾸미지 않음.
- 앱 시작부터 정체: 기준선 획득 후 7초부터 판단. 시작 전 정체 시간을 추정하지 않음.
- 알림 후 실제 증가 확인: 새로운 episode를 위해 재무장.

상태는 DISARMED/BASELINING/TRACKING/STALLED/UNKNOWN. 화면 숫자 업데이트 주기와 OCR 지연 때문에 게임 내부의 정확한 중단 시각과 차이가 있을 수 있다. 합격 기준은 화면에 나타난 마지막 증가를 기준으로 측정한다. 메뉴·로딩 중 정책은 별도 확인하며 기본은 해당 ROI 관측 불가 시 보류한다.

### 5.4 거짓말 탐지기 등장

입력: 중앙 우선 영역 + 축소 전체 화면. 고정된 중앙 좌표만 사용하지 않는다. 팝업 외곽·고유 장식·버튼 배치의 결합으로 후보를 찾고, 필요하면 제목/고정 안내문 OCR 또는 팝업 분류기로 재확인한다. 캡챠 문제의 내용을 읽거나 풀 필요는 없다.

일반 대화창·퀘스트·시스템 경고와 구별한다. 강한 복합 근거가 0.3초 이상 유효 3회 관측되면 긴급 이벤트. 애매한 후보는 짧은 추가 관측으로 확인하고 너무 높은 단일 임계값 때문에 변형 팝업을 놓치지 않도록 이벤트 재현율을 우선 튜닝한다.

최고 우선순위로 소리를 재생하고, 기본 5초 간격으로 사용자가 확인하거나 팝업 소멸을 확인할 때까지 반복한다. 확인 버튼은 알림만 멈추며 게임에 입력하지 않는다. 가림·캡처 장애 중에는 존재 여부 미상으로 표시하고 새 확정 판정을 하지 않는다. 자동 소멸 확인은 유효 부재 1초를 초기값으로 한다.

### 5.5 부스터 잔여시간 및 종료

중앙 상단 타이머를 전용 ROI로 추적한다. 타이머 배경·위치·고유 외형으로 다른 콘텐츠의 타이머와 구분한다. 형식은 사용자 화면에서 확인한 뒤 정수 초, m:ss 등 허용 문법을 지정한다. 100초는 사용자 제공 지속시간이다.

초 단위 잔여시간을 필수 출력한다. 활성 여부만 반환하는 구현은 불합격이다. 중간에 앱을 켜도 화면의 잔여시간으로 즉시 동기화하고 100초를 새로 시작하지 않는다. OCR을 초당 4회, 표시 갱신을 초당 10회 초기값으로 한다. 시간 역행은 재사용·연장 후보로 반복 확인하며 갱신 후 episode를 구분한다.

0초 도달과 타이머 소멸을 함께 확인하면 종료 이벤트. 타이머가 일찍 사라지거나 가려지면 UNKNOWN, 마지막 신뢰 관측에서 계산한 만료는 예상으로 분리한다. 타이머가 1초에서 바로 사라지는 실제 UI라면 검증된 소멸 규칙과 만료 구간을 함께 사용한다. 전용 몬스터 소멸은 종료 확정 근거로 쓰지 않는다.

### 5.6 잔여시간 추정기 — 필수 기능

공통 출력: {status, remaining_seconds, display_value, resolution_seconds, source: observed|propagated|estimated|unknown, observed_at, uncertainty_seconds, lower_bound, upper_bound}. 판정 불가를 0초로 표시하지 않는다.

- 부스터: 초 단위 표시·추적 필수.
- 비약: 30분~10분 구간은 분 단위, 10분 미만은 초 단위 표시·추적 필수.
- 비약 10분 경계는 단순 숫자 포맷 변경이 아니라 정밀도 요구 변화다. 불확실 구간이 600초 경계를 걸치면 초 단위 확보를 우선 시도하고 정밀도 미달을 명시한다.

OCR 값 r_i를 관측한 monotonic 시각 t_i와 결합하여 예상 만료 E_i=t_i+r_i를 구한다. 실제 표시의 올림/내림과 갱신 주기를 먼저 검증한다. 예를 들어 내림 정수 초라면 실제 잔여는 [r_i,r_i+1)이고, 내림 분 표시 m이라면 [60m,60(m+1))이다. 관측 간 만료 구간의 교집합과 이상치 제거로 범위를 좁힌다. 교집합이 없으면 OCR 오류 또는 갱신 후보로 재확인한다.

유효 관측 사이에는 monotonic 경과시간으로 남은 시간을 갱신한다. 짧은 OCR 누락 시 propagated로 표시하되 불확실도를 유지한다. 긴 가림·절전·재시작은 unknown 또는 estimated로 강등하며 화면 재동기화가 필요하다. 초 숫자를 그리는 것과 초 단위 정확도를 확보하는 것은 다르다.

비약 아이콘 명암은 보조 측정이다. 아이콘 원형과 시간 글자를 분리하고 명암 경계/밝은 면적의 비율을 추출한다. 시간과 명암의 관계가 선형인지, 방향·계단 크기가 어떤지는 실제 여러 잔여시간 표본으로 보정한다. 1,800초 효과에서 1초는 전체의 약 0.056%이므로 작은 아이콘 명암만으로 1초 분해능을 보장할 수 없다. OCR 모순 검출·대략 시간 확인 용도로 우선 사용한다.


#### 비약 시간 표시 모드 전환 — 사용자 확인 반영

MINUTES 모드: 아이콘 좌하단 ROI에서 저채도·고명도 흰색 글자를 분리한다. 분 숫자를 읽고 10~30 범위 및 실제 분 표시의 올림/내림 규칙을 검증한다. 아이콘의 전체 명암 변화가 글자 분할에 미치는 영향을 테스트한다.

SECONDS 모드: 아이콘 중앙 ROI에서 노란색 글자를 색상 분할하고 m:ss 문법으로 읽는다. 0≤m≤9, 0≤ss≤59를 검증하여 r=60m+ss로 변환한다. 숫자 위에 아이콘 그림이 비치는 경우 원본·마스크 두 후보의 일치도를 활용한다.

10분 경계 부근에서는 두 ROI를 함께 읽는다. 노란색 m:ss가 시간에 걸친 유효 관측 2회에서 확인되면 SECONDS 모드로 전환한다. 한 프레임 색상 변화나 깜빡임만으로 모드를 바꾸지 않는다. 반대로 노란색이 사라지고 흰색 분 표시가 나타나 시간이 크게 증가하면 재사용/갱신 여부를 확인한다.

중간 실행이 9:59 상태여도 직접 읽어 초 단위로 동기화할 수 있다. 초기 동기화 목표는 선명한 화면에서 1초 이내이며 실측으로 검증한다. 숫자가 가려지면 해당 관측을 UNKNOWN으로 처리하고 마지막 신뢰값에서의 보간에 출처를 표시한다. 아래 초 표시 미존재 대안은 향후 UI 변경에 대한 예외 경로이며 현재 환경의 기본 경로가 아니다.

비약에서 초가 직접 보이지 않는 경우의 결정 순서:
1. 화면에 초 단위 값이 존재하면 그 ROI를 읽는다.
2. 분 표시 변화 시점을 연속 관측하고 실제 반올림 규칙을 알면 경계 시점에 맞춰 동기화한다. 4 Hz 관측 시 표본 지연 외 UI 갱신 지연도 오차에 포함한다. 최초 동기화 전에는 범위로 표시한다.
3. 시작 순간을 관측한 경우 1,800초 타이머를 보조 사용하되 실제 서버/UI 시각과 차이를 검증한다.
4. 실행 중간·초 표시 없음·분 경계 미관측이면 즉시 초 단위 정확값은 식별 불가능할 수 있다. 이 경우 '동기화 대기'로 표시하고 추가로 관측 가능한 시간 표시를 사용자에게 요청한다. 명암이나 분 표시에서 임의로 정확한 초를 만들어내지 않는다.

시간 정밀도 합격 조건은 부스터와 비약 10분 미만에서 독립 기준 대비 오차 1초 이내를 초기 제안한다. 사용자 요청의 '초 단위'에 맞춘 검증 목표이며 실제 표시의 정밀도·지연 확인 전 보장은 아니다. 비약 10분 이상은 실제 UI의 분 표시 규칙과 일치해야 한다. 만료 예상만 제공하고 잔여시간 정확도 검증을 생략한 결과는 완료로 인정하지 않는다.

## 6. 알림·장애 처리

이벤트: {id, type, episode_id, first_seen, confirmed_at, certainty: confirmed|estimated, reason, profile_version, evidence_ref}.

우선순위는 탐지기 > 사냥 중단 > 룬 > 비약/부스터로 초기 제안한다. 높은 우선순위는 낮은 소리를 중단할 수 있고, 미전달 이벤트는 만료시간 내 재생한다. 해결되어 의미가 없어진 대기 이벤트는 폐기한다. 동일 episode는 중복 제거하며, cooldown 때문에 새로운 실제 이벤트가 사라지지 않게 한다.

오디오 큐는 길이를 제한한다. 장치 변경·음소거·재생 실패를 UI에 표시하고 다른 기본 장치로 재시도한다. 소리 테스트를 첫 설정에 포함한다. 전체 음소거·이벤트별 활성화·긴급 반복 중지 기능을 둔다.

캡처 끊김은 2초 후 건강 상태 경고 후보, 3초 후 별도 알림을 초기값으로 한다. 자동 재연결은 제한된 지수 백오프로 수행한다. 정상 캡처와 앵커 재획득 후에만 판정 재개한다. 사용자의 의도적인 감시 중지는 장애 알림을 만들지 않는다.

```text
src/astra_test/

  alerts/                 # 우선순위·중복·장치·소리
  storage/                # 설정·이벤트·선택적 근거
  ui/                     # 초기 설정·상태·진단

assets/sounds/

 tests/                   # 구현 단계에서 생성
 tools/                   # 수집·라벨·재생 평가
```

이 구조는 예정이며 아직 구현 파일은 생성하지 않았다. detector는 화면을 읽어 관측만 반환하고 직접 소리를 재생하지 않는다. 상태 로직은 실제 시계 대신 주입 가능한 clock을 받아 녹화에서 동일 결과를 재현한다.

```text
on_frame(frame):
  if invalid(frame): publish_health(); suspend_affected_detectors(); return
  rois = locate_and_validate(frame)
  for detector in due_detectors(frame.timestamp):
    observation = detector.observe(frame, rois)
    if stale_or_wrong_epoch(observation): continue
    event = state[detector].advance(observation, frame.timestamp)
    if event: alert_queue.offer(event)
```

기본은 로컬 처리, 연속 원본 녹화 비활성. 오류 분석용 자료 저장을 켜면 이벤트 주변 ROI만 보관하고 닉네임·채팅 등은 마스킹한다. 보관량·기간은 설정 가능하게 한다. 모델 업데이트 시 템플릿·설정·코드 버전을 함께 기록하고 이전 버전으로 되돌릴 수 있게 한다.
