# Astra Web — 메이플스토리 화면 관측

Chrome의 화면 공유로 게임 화면을 보고 **경험치 정체 · 룬 등장 · 비약 종료 · 부스터 종료 ·
거짓말 탐지기 등장**을 소리로 알리는 로컬 웹 앱입니다.

화면을 **보기만** 합니다. 게임 입력 자동화, 문제 해독·응답, 프로세스 메모리 접근은 하지 않습니다.

```powershell
cd C:\Coding\astra_test
.\serve.ps1
```

| 주소 | 용도 |
|---|---|
| `http://localhost:8000/` | 관측 화면 |
| `http://localhost:8000/selftest.html` | 이미지 회귀 시험 (브라우저) |
| `node tools\state_tests.js` | 순수 판정 로직 시험 (브라우저 불필요) |

서버는 `127.0.0.1`에만 바인딩합니다. 이미 떠 있으면 그대로 재사용하세요.

## 1. 부스터 종료 판정 — 시간을 재지 않습니다

사용자 규칙(2026-09-06)을 그대로 구현한 것이며, 이 프로젝트에서 가장 중요한 동작입니다.

> 1. 시간을 측정하지 않는다. 중요한 것은 ‘남은 시간’ **UI 가 존재하느냐**이다.
> 2. ‘남은 시간’이 존재했다가 **사라졌을 때**, ‘룬 지속시간’을 확인한다.
> 3. 룬 지속시간이 **1분 50초 이상**이면 부스터 종료 알림을 울린다.
> 4. 현재 UI 탐지 성능은 유지하고 트리거만 바꾼다.

### 어떻게 판정하는가

```
UNSEEN ──PRESENT×2──▶ VISIBLE ──ABSENT──▶ DISAPPEARANCE_CANDIDATE
                         ▲                          │ABSENT 재확인
                         │PRESENT×2                 ▼
                      RESOLVED ◀────────────── CHECK_RUNE
                                   룬 ≥110초 → 알림 1회
                                   룬 <110초 / 룬 없음 → 알림 없음
                                   끝내 못 읽음 → ‘종료 확인 불가’
```

- 부스터 숫자는 **아예 읽지 않습니다.** `BoosterDetector.observe()`는 템플릿 정합 한 번만 하고
  `PRESENT / ABSENT / UNKNOWN`을 돌려줍니다. 결과 객체에 `remaining_seconds`도, 만료시각도 없습니다.
- 룬 지속시간은 **UI가 사라진 그 프레임**에서 읽은 값을 씁니다. 확인 프레임에서 1:50이 1:49로
  바뀌어도 후보 프레임 근거가 우선입니다.
- `UNKNOWN`(공유 단절·보정 중·오래된 결과·무효 프레임)은 **절대 소멸로 치지 않고**, 대기 중인
  소멸 건을 취소하며 재무장을 요구합니다. 깜빡임 한 프레임도 소멸이 아닙니다.
- 소멸 건마다 ID(`D1`, `D2`…)가 붙고 알림은 건당 정확히 한 번입니다.

### 룬 지속시간 아이콘

`config/labels.json`에서 `"role": "rune_duration"`인 항목이며, **사용자가 확인해 준 것만** 씁니다.

| ID | 아이콘 | 근거 |
|---|---|---|
| `U13` | 밝은 파랑 구름 (4:07) | 2026-09-06 사용자 확인: “U13 이 룬 아이콘이며, 해당 사진의 지속 시간은 4:07 이다.” |
| `U19` | 짙은 파랑 구름 (2:12) | 2026-09-06 사용자 확인: “조금 더 짙은 파란색의 아이콘… 그 아이콘도 룬 아이콘이다.” `Maple_260906_023211.png` (1075,40)에서 추출 |
| `U12` | `U13`의 1분 미만 표시 (22) | 아이콘 아트가 U13과 동일(상단 patch 정합 0.9994). 별칭 처리해 중복 매칭 방지 |

- **룬 아이콘이 여러 개면 남은 시간이 가장 긴 것을 채용합니다** (사용자 규칙 2026-09-06).
- 1분 미만이면 게임이 `m:` 없이 초만 표시하므로, 같은 캡처를 초 문법으로 다시 읽고
  색상 마스크 판독과 일치할 때만 인정합니다.
- 미니맵의 `rune_marker.png`는 **룬 등장 마커**이지 지속시간 아이콘이 아닙니다. 서로 다른 기능입니다.

### 화면의 카운트다운은 싱크 후 자동 타이머 — 판정과 무관합니다

사용자 요청(2026-09-06)에 따라 시각적 완성도를 위해 표시만 합니다 — `src/display.js`.

- **부스터**: UI를 탐지하면 화면 숫자를 **1회만 읽어 싱크**하고, 이후 자동 타이머로 흘러갑니다.
  싱크한 값이 0을 지나도 UI가 남아 있으면 `서버 지연 대기중 . / . . / . . .`(0.5초 주기).
- **비약**: 아이콘을 탐지하면 마찬가지로 1회 싱크한 뒤 자동 타이머. 추가로 숫자 영역을
  **약 1초에 한 번 변화 감지**하여, 바뀌는 즉시 다시 싱크하고 자동 타이머로 돌아갑니다.
  이것이 분 표시를 정확하게 만듭니다 — `29`는 1740~1799초를 뜻하지만, `28`로 바뀌는
  그 순간의 잔여시간은 정확히 1680초입니다.

숫자는 **이 표시를 맞추는 데에만** 쓰입니다. 부스터 알림은 여전히 `BoosterUiState`가
UI 소멸 + 룬 ≥110초로만 내고, 비약 종료는 `BuffExpiry`가 아이콘 존재로만 냅니다.
카드에도 `표시 타이머 … (판정과 무관)`으로 적힙니다.

## 2. 그 밖의 판정

| 대상 | 판정 근거 |
|---|---|
| 경험치 정체 | **숫자를 읽지 않습니다.** 경험치 글자 영역의 화소가 8초 이상 변하지 않으면 정체. 변화만이 재무장합니다. |
| 비약(P04) | 마지막 구간(숫자 미표시)을 본 뒤 아이콘이 사라지면 종료. 시간 많이 남은 소멸은 ‘확인 불가’로 닫고 다시는 발화하지 않습니다. |
| 룬 등장 | 검출된 미니맵 안에서 분홍 마커 템플릿 + 색상 조건, 2회 확인. |
| 거짓말 탐지기 | 한 후보 위치에서 구조적으로 일치하는 근거가 있을 때만. 얇은 띠 하나로는 발화하지 않습니다. |

### 경험치 — 왜 숫자를 안 읽는가

사용자 지적(memo): *"해당 섹션의 목적은 이미지가 변하는가에 대한 탐색이다."*
실측상 이 화면의 경험치 OCR은 프레임마다 0.84~0.92로 흔들리고 값이 한 자리씩
달라져, 정체 판정을 숫자에 걸면 대부분의 시간이 `판독 보류`가 됩니다.

이제 밝은 글자 화소의 열별 분포를 서명으로 삼아 변화만 봅니다. 실측 근거:

```
같은 프레임 두 번            변화량 0
경험치가 다른 두 실화면      변화량 179     (임계 6 → 30배 여유)
글자가 사라진 합성 프레임    변화량 800
```

영역은 OCR 없이 픽셀 투영으로 찾고, 못 찾으면 memo가 허용한 화면 최하단 중앙을 씁니다.
스트림이 얼어 같은 프레임이 계속 들어오는 경우는 전체 화면 서명으로 구분해
정체로 세지 않습니다. 숫자는 화면 표시·기록용으로만 3초에 한 번 읽습니다.

### 소형 재물 획득의 비약 vs 소형 경험 축적의 비약

두 물약은 아이콘 상단이 사실상 동일하고, **표시 모드가 바뀌면 검출 자체가 실패했습니다.**
2026-09-06 실측:

```
분 표시("29")   상단 patch 정합  0.997   → 검출됨
시계 표시("4:24") 상단 patch 정합  0.852   → 임계 0.90 미달로 아예 미검출
```

숫자 뒤 검은 띠가 상단 patch(2~9행)까지 침범해 정합이 떨어집니다.
금색 화소 signature도 시계 표시에서는 노란 숫자에 오염되어 **재물 35 / 경험 33**이 되어
구분이 깨졌습니다(위치·색 조건 4,685개 전수 탐색 결과 절대 기준 분리 영역 없음).

해결:
- 표시 모드별 템플릿을 각각 등록(`P04c` / `P05c`)하고 `match_min`을 0.80으로 내림
- 구분은 색이 아니라 **주머니 하단 `[16,23,8,4]`에서 두 비약 템플릿과의 상관 비교**.
  자기참조 템플릿을 제외하고도 4개 실셀 전부 정확 분류, 마진 **0.99 vs 0.83**

### 버프 격자 범위 — 넓히는 데만 씁니다

memo 제안대로 버프 아이콘의 실제 경계(우상단 고정, 좌·하단은 아이콘에서)를 계산합니다.
다만 이것으로 탐색 범위를 **좁히지는 않습니다.** 나란히 붙은 두 아이콘의 윤곽이 하나로
합쳐지면 `iconCandidates`가 한 개만 돌려주고, 그 하나로 만든 범위가 나머지 아이콘을
잘라내 영원히 못 찾게 되는 것이 시험에서 재현됐습니다. 그래서 기본 범위와 **합집합**을
취해, 버프 줄이 180px 아래로 내려가면 따라 내려가되 좁아지지는 않게 했습니다.

## 3. 세션과 재시작

- 중지·공유 종료 시 워커를 **terminate**하고 스트림·프레임 사본·판정 상태를 모두 정리합니다.
- 다시 공유하면 **새 sessionId로 워커를 새로 만듭니다.** 이전 세션의 뒤늦은 결과는 폐기됩니다.
- 모든 메시지에 `sessionId / calibrationId / frameId`가 붙습니다.
- fps·프레임 수·이벤트는 세션별로 셉니다. 처리가 멈추면 `처리 정지 —`가 앞에 붙습니다.
- 중지·공유 종료·실패의 버튼 상태는 `syncControls()` 한 곳에서만 바뀝니다.

### 보정

- **워커가 준비된 뒤에** 후보 평가를 시작합니다.
- 후보를 바꿀 때마다 `calibrationId`가 올라가고, 그 이전 결과는 버려집니다.
- 성공 조건은 문법 통과 하나가 아니라 **잘림 검사까지 통과한 경험치 확정값 + HUD 근거 2개 이상**
  (미니맵·버프영역·유효화면)입니다.
- 보정 중에는 알림을 보류합니다.
- 2026-09-06 실측: 공유 표면 1368×800, 바깥 테두리 1px, 제목줄 31행 → 클라이언트는 `(1, 31, 1366×768)`.
  후보 1번이 이 값을 표면 크기에서 직접 계산합니다(‘8px/39px’ 추정은 1352×760으로 빗나갔습니다).
- 후보당 7초를 주고, 전부 실패하면 근거가 가장 많은 후보를 차선으로 채택합니다.
- 미니맵은 한 번 찾으면 그 자리를 재사용하고, 3초 이상 확인되지 않을 때만 다시 찾습니다.

## 5. 화면 크기 고정

설명 문구가 실시간으로 바뀌어도 레이아웃이 움직이지 않도록, 글이 들어가는 칸은
모두 크기를 고정하고 넘치면 감춥니다(카드 176px, 크롭 패널 262px, 보정 56px,
로그 280px, 버프표 320px…). 긴 토큰 하나가 칸을 넓히지 못하도록 가로도 클램프합니다.

극단적으로 긴 문구를 모든 칸에 넣어도 카드·크롭·섹션·본문 높이가 **한 픽셀도
변하지 않고 가로 스크롤도 생기지 않는** 것을 브라우저에서 측정해 확인했습니다.

## 6. 진단 화면 읽는 법

상태 표시는 다음을 구분합니다:
`공유 전 / 중지됨 / 공유 중단됨 / 초기화 중 / 워커 초기화 실패 / 보정 중 / 새 캡처 없음 /
분석 지연 / 버프 영역 가림 / 관측 불가 / 정상`

- 검출기별 크롭은 **그 검출기가 실제로 분석한 프레임**을 역할별로 보관했다가 그립니다.
  좌표 옆 `frame#`이 그 프레임 번호이고, `(결과 frame#…)`이 붙으면 판정 프레임과 다르다는 뜻입니다.
- 경험치 카드는 실패했을 때 **무엇을 읽었는지**와 보류 사유를 같이 보여줍니다.
- 부스터 카드는 UI 존재/앵커 점수, 상태기계 상태, 소멸 건 ID, 룬 원문·초, 알림/억제 이유를 보여줍니다.
- 버프 표의 마지막 열은 그 항목이 마지막으로 판독된 시각입니다. 오래된 항목은 ‘이전 판독’으로
  표시되며 최신값으로 쓰지 않습니다.

## 7. 성능 (2026-09-06, 사용자 PC · Chrome · 1368×800 공유)

| 경로 | 처리시간 | 비고 |
|---|---|---|
| 부스터 UI 존재 판정 | **17–23 ms** | OCR 없음. 앵커 정합 한 번 |
| hud 전체 (부스터+룬+P04+미니맵) | 91–98 ms (룬 없을 때) / 546–557 ms (룬 판독 시) | 룬 소멸 판정에 필요한 프레임 결합 비용 |
| 경험치 숫자 판독 | **1.2 ms** | 글꼴 정확 대조. 기존 OCR 324 ms 대비 약 270배 |
| 경험치 (프레임 전체) | 16–35 ms · 8.3 fps | 변화 감지 + 글꼴 대조 |
| 전체 버프 목록(44개) | 7.5–11.4 초 | 항목별로 도착, 낮은 우선순위 |
| 거짓말 탐지기 | 1.7–7.0 초 | 템플릿 근거 없으면 OCR 폴백을 3회당 1회만 |

- 부스터 UI 결과 0.5초 이내 목표: **달성**(17–23 ms).
- 룬 조건 확인 2초 이내 목표: 후보 프레임에 이미 룬 판독이 실려 있어 **hud 1주기 내(≈0.6초)** 결정.
- 전체 버프는 여전히 느립니다. 개선한 부분은 항목별 반환·양보와 분/초 판독 조기 종료입니다.

## 8. 시험

```powershell
node tools\state_tests.js          # 67개 — 순수 판정 로직
```
브라우저에서 `selftest.html` — 83개 (이미지 회귀 + 실화면 표본).

시험 표는 근거를 구분해서 표시합니다:
- `[실화면]` 이 저장소에 있는 실제 게임 캡처
- `[합성]` 조건을 만들려고 시험 코드가 편집한 이미지

## 9. 남은 제약 · 미검증

- **부스터 종료 알림이 실제로 울리는 장면은 실게임에서 아직 못 봤습니다.** 실측한 소멸 건은
  룬이 1:31(91초)이라 규칙대로 억제됐습니다. ≥1:50 경로는 실제 U13/U19 아이콘 픽셀
  (4:07·2:12)과 순수 상태 시험으로만 확인했습니다.
- 거짓말 탐지기 **양성**은 참조 자산 자체(자기참조)로만 확인했습니다. 독립적인 실제 팝업 캡처가
  없어 `D` 경로(단일 정보량 큰 영역, 0.90 하한)의 실전 적합성은 미검증입니다.
- 백그라운드 탭·최소화·절전에서의 장시간 동작은 시험하지 않았습니다.
- 장시간 메모리 증가(Mat/bitmap 누수)는 계측하지 않았습니다.
- 경험치 **숫자**는 이 화면에서 여전히 프레임당 판독이 불안정합니다(0.84–0.92). 이제 정체
  판정은 숫자를 쓰지 않으므로 영향이 없지만, 카드에 보이는 숫자는 가끔 `판독 보류`로 남습니다.
- **30분 연속 표본 녹화**: 관측 화면을 `http://localhost:8000/?rec=30` 으로 열고
  평소대로 화면을 공유하면, 보정이 안정된 뒤 1초 간격 무손실 캡처가 스스로
  시작됩니다(`assets/samples/rec_<시각>/`). `?rec=` 이 없으면 녹화기는 적재되지
  않습니다. 30분에 약 2.4 GB. 절차와 근거는 `AGENT_HANDOFF.md` 부록 D.
- 글꼴 대조는 **저장 표본**에서만 검증했습니다. 실화면 재검증이 남아 있습니다.
- 아틀라스는 이제 세 글꼴입니다 — 경험치, 버프 아이콘 중앙의 노란 숫자
  (`29` · `1:51`), 버프 아이콘 좌측 하단의 흰 분 숫자(`13`). 부스터 숫자는
  사용자 지시대로 OCR을 그대로 씁니다.
- `buff_minutes` 아틀라스에 실린 숫자는 **0·1·2·3뿐**입니다(표본에 그것만
  나왔습니다). 4~9는 실전에서 처음 만나면 한 번 거부되고, OCR이 읽은 값으로
  학습됩니다. 학습분은 워커 메모리에만 남아 새로고침하면 사라집니다.
- 룬이 여러 개일 때 전부 찾도록 한 수정(FIX-13)은 저장 표본 회귀까지만 통과했고,
  실화면 재검증이 남아 있습니다.
- 버프가 180px 아래로 내려간 실캡처가 없어, 격자 범위 확장은 합성 조건으로만 확인했습니다.
- 표면 크기·창 테두리는 환경마다 다릅니다. 1368×800은 **이 PC의 실측값**이지 상수가 아닙니다.
